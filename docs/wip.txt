## Current State: Class Table Fixed, DNUs Greatly Reduced

### Summary
Fixed three significant bugs reducing DNUs from ~50 per run to ~2-3 per run.

### DNU counts (current)
- Deterministic DNUs: 2 per run (image-side issues, NOT VM bugs)
- Sporadic DNUs: 0-1 per run (~20% of runs have 1 sporadic DNU)
- Previous: ~50% of runs had sporadic DNUs, ~3-19 non-deterministic per run

### Changes Made (this session)

1. **Fixed class table building** (commit 6891665)
   - The 4th object in old space is freeListsObj (64 zero slots), NOT hiddenRootsObj
   - hiddenRootsObj is the 5th object with 4096 class table pages + 8 extra roots
   - Was using hardcoded offset 0x248 and reading 100 "pages" from wrong data
   - Now properly walks objects (objectAfter pattern) to find the 5th object
   - Correctly finds 23 pages with 20842 classes

2. **Fixed context state sync on process switch** (commit 9be2ffe)
   - When frameDepth_==0, materializeFrameStack returned activeContext_ with stale PC/stackp
   - The context's IP and stack hadn't been updated since it was last restored
   - Now syncs interpreter's current IP, stackp, and stack values back into the context
   - Reduced sporadic DNUs from ~50% to ~30% of runs

3. **Save block closure in SavedFrame** (commit a888326)
   - Block activation now saves the FullBlockClosure in SavedFrame.savedClosure
   - materializeFrameStack sets context slot 4 (closureOrNil) correctly
   - Previously always set to nil, breaking block contexts after process switch
   - Reduced sporadic DNUs from ~30% to ~20% of runs

### Previous changes (already committed)
4. **forceYield same-priority only** — only yield to same priority (round-robin)
5. **numTemps fix in pushFrame()** — push numTemps-argCount nils, not numTemps
6. **Enhanced DNU logging** — sender chain dump, receiver details

### Deterministic DNUs (image-side, NOT VM bugs)
1. **`#handleClassChange:` on ByteSymbol** (step ~1592684)
   - Subscription handler receives ByteSymbol instead of handler object
   - Caught by `on:do:` exception handlers
   - Same happens in standard VM (just not logged)

2. **`#printStringHex` on UndefinedObject** (step ~1793629)
   - Epicea changelog nil counter during startup
   - Caught by exception handlers

### Remaining Sporadic DNUs (~20% of runs)
- `#nextPut:` on nil — nil stream during timer preemption
- `#ensure:` / `#<=` / `#mergeWith:` on Array — wrong object in frame
- Caused by timer preemption (pri=80 > active=79) during frame materialization
- Root cause: expression stack saving in materializeFrameStack may have
  off-by-one errors computing boundaries between frames

### Key Insights
1. In Spur 64-bit old space: nil, false, true, freeListsObj, hiddenRootsObj
2. hiddenRootsObj has 4096+8 slots (overflow header), NOT the 64-slot object at 0x30
3. When frameDepth_==0, activeContext_ must be synced before process switch
4. Block frames need their closure saved for correct materialization

### Next Steps
1. **Fix expression stack boundaries** — the remaining sporadic DNUs suggest
   the expression stack saving in materializeFrameStack has edge cases where
   items are saved incorrectly. The boundary calculation between frames
   (exprStart to nextFrameStart) may be off.
2. **Add closure_ to interpreter state** — track current frame's closure so
   the current frame can also be materialized with correct closureOrNil.
3. **Test with full app** — build Mac Catalyst to verify UI rendering.
