## Two GCC compile breaks since `78d0cba`

Mac-side commits between `78d0cba` and `cbfa58f` added two things gcc
chokes on but Apple clang accepts.  Fixed in commit `641effc3`
(this session):

  - `Interpreter.cpp` uses `__builtin_debugtrap()` (clang/MSVC only).
    Added a `PHARO_DEBUGTRAP()` shim that maps to `int3` on x86, `brk
    #0` on aarch64, `__builtin_trap()` elsewhere.  Both call sites
    are env-var-gated SP-corruption diagnostics, never on the hot
    path.

  - `src/platform/jit_jmsize_other.cpp` references
    `pharo::jit::JITMethod`, which is gated under `PHARO_JIT_ENABLED`.
    The CMake source-list gate on lines 183-189 includes the file
    even when JIT is disabled.  Wrapped both `jit_jmsize_*.cpp` files
    in `#if PHARO_JIT_ENABLED` to mirror what `JITRuntime.cpp` does
    with its body — keeps the source list and content guard
    decoupled.

## Tier-1 JIT on Linux x86_64 — already runs

Two pieces of news from the Mac side make tier-1 JIT functional on
x86_64 today (with `PHARO_NO_SISTA=1`):

  - `extract_stencils.py` produced `generated_stencils_x86_64.hpp`
    (203 KB, committed at `9e3f05e5` or thereabouts) with
    pre-extracted x86_64 stencil bytes.  These were extracted on Mac
    (`-target x86_64-apple-macos14`), but x86_64 SysV ABI is
    compatible enough between Apple and Linux for the JIT-runtime
    helper calls these stencils make.  Stencils run.

  - `JIT_CALL` macro in `JITState.hpp:217-225` has a plain C
    function-pointer fallback for non-arm64 hosts; this is the path
    Linux x86_64 takes (no inline asm, no trampoline).

  - `TrampolineAsm.S` is `__aarch64__`-gated and skipped on x86_64.
    The C++ fallback dispatch in `Interpreter.cpp:17188+` is the
    interpreter's "send-bail and re-enter" loop on x86_64.

What ISN'T running on x86_64 yet:

  - SimStack optimization: `applySimStack()` in `JITCompiler.cpp` is
    `#ifdef __aarch64__`.  Worth ~10-20% on tight loops.
  - Hand-written x86_64 J2J trampoline: parallel of TrampolineAsm.S.
  - Tier-2 / Sista lowering: see below.

Pending: SUnit run with JIT-on / Sista-off to confirm tier-1
correctness parity with no-JIT.  If pass rate matches no-JIT, the
copy-and-patch path is sound.

## Tier-2 / Sista x86_64 port — the real remaining work

`SistaLowering.cpp` (5237 lines) and `Tier2Compiler.cpp` (2267
lines) emit asmjit `a64::*` ops directly.  Audit findings:

  - The IR walker shape is portable.  Asmjit virtual regs +
    struct-offset addressing don't bake in arm64 hardware
    assumptions.

  - The arm64-specific code is in 15 scoped `using namespace
    asmjit::a64` blocks in SistaLowering.cpp, plus ~200-300 lines
    in Tier2Compiler.cpp.

  - Concrete instruction differences:
        ldr/str        →  mov (memory operand on x86)
        csel           →  cmov / branch-fusion
        cbz / cbnz     →  test + jz / jnz
        lsl/asr/lsr    →  shl / sar / shr
        b_eq / b_ne    →  je / jne
        a64::CondCode  →  x86::CondCode (different enum values)

  - Calling convention: arm64 uses x0=state; x86_64 SysV uses
    rdi=state.  asmjit handles arg passing via FuncSignature so
    this is essentially a one-line change per function.

Estimated 600-1000 lines of new x86_64-specific lowering.

## Next moves

In dependency order:

1. **SUnit-Sista-off baseline.**  Run the same 565-class test list
   against the JIT-on / Sista-off build.  Tier-1 should match no-JIT
   pass rate (within a few % tolerance for timing tests).  This is
   the regression baseline for all subsequent x86_64 JIT work.

2. **Sista x86_64 lowering, op by op.**  Don't rewrite SistaLowering
   in one go; gradual port.  On x86_64, fall through to "lowering
   not implemented" (`*failedAtValue = vid; return nullptr`) for
   any IR op without an x86_64 emit branch — that triggers Sista's
   safety bail and the method runs under tier-1 instead.  Start
   with the simplest ops that are exercised by `tinyBenchmarks` /
   `block(500K)`:
       kLoadReceiver, kLoadTrueOop, kLoadFalseOop  (ldr → mov reg, [base+off])
       kLoadTemp, kLoadLiteral, kLoadInstVar       (ldr → mov)
       kStoreTemp, kStoreInstVar (helper invoke)   (str → mov [base+off], reg)
       kReturn                                      (ret with state+exit)
       kPrimAddInt / kPrimSubInt / kPrimMulInt      (add/sub/imul + JO)
       kPrimLtInt / kPrimEqInt / etc.               (cmp + setcc / cmov)
       kBranch / kBranchIfTrue / kBranchIfFalse     (jmp / jcc)
   That's the "make tinyBenchmarks Sista-compile" subset.  Each new
   op lands with a SistaIR round-trip test.

3. **Bench parity with arm64 Linux (Pi 5).**  Mac side already ran
   `block(500K)` on Pi 5 at 134ms.  When Sista x86_64 lands, run the
   same bench on this box and on Pi for direct A/B.  If x86_64
   matches Pi within ~30%, the port is correct.  If it's much
   slower, profile (`perf record` is wired up already on Linux).

4. **SimStack on x86_64** (perf, ~10-20%).  Lift the
   `#ifdef __aarch64__` in `JITCompiler.cpp:946-1231` and write the
   x86_64 equivalent (uses r12-r15 instead of x19-x22 — both are
   callee-saved in their respective ABIs).

5. **Hand-written x86_64 J2J trampoline** (perf).  Optional;
   parallel of `TrampolineAsm.S` for the J2J chain.  C++ fallback
   already works.
