## JIT vs NO_JIT perf measurement (2026-04-24)

Simple eval-mode benchmarks:

    Workload                             JIT eager    NO_JIT    speedup
    100M iteration arithmetic loop       4415 ms      4467 ms   1%
    fib(30) recursive send-heavy         198 ms       213 ms    7%

The small wins reflect our stencil-based JIT: T1 tier uses the
same template stencils as the interpreter, so code-gen is similar.
Savings come from inline method prologues, IC hit paths, and
inlined primitives.  Larger wins would need T2 (asmjit) default-on
(currently opt-in via PHARO_T2=1), bigger ICs (>6 entries), or
method inlining — all non-trivial architectural work.

## JIT performance regression on heap-walking workloads

Cross-check with same 180s budget and ArrayTest warmup:

    ProtoObjectTest  NO_JIT  15/15 pass  <180s
    ProtoObjectTest  JIT     12+ tests run, timeout

JIT is slower than interpreter on these tests.  Profile (from
earlier run): IC 91.5% hits, 71K noSelBits misses, 12K polymorphic
misses.  Heap walks (testPointersTo, testNextObject) hit megamorphic
dispatch through objects of every class.  JIT compile cost +
PIC-miss overhead exceeds the per-instruction savings.

This is a performance item, not a correctness item.  Same pattern
likely applies to the other 18 JIT "timeouts" — introspection,
trait composition, and crypto all exercise megamorphic send sites
at high volume.
