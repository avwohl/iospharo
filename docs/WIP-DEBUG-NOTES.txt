CHANGES MADE:
1. Fixed Oop tag encoding for Spur 64-bit:
   - SmallInteger tag: 1 (001)
   - Character tag: 2 (010)
   - SmallFloat tag: 5 (101)
   - Object pointer tag: 0 (000)

2. Fixed fromObject() - no longer encodes space in low bits
   (Spur 64-bit uses tag 0 for all object pointers)

3. Modified syncDisplayToSurface() to always use renderWorldMorphs()
   instead of copying from Display Form (BitBlt not yet working)

4. Added skip for black morphs in renderMorph()
   (These are typically text areas or content panels)

5. Fixed SmallFloat64 decoding algorithm:
   - Changed exponent offset from 0x3800000000000000 to 0x7000000000000000
   - Offset represents 896 << 53 (in rotated position where sign is at LSB)
   - Algorithm: remove tag >> add offset >> rotate right to restore sign bit
   - Reference: https://clementbera.wordpress.com/2018/11/09/64-bits-immediate-floats/

6. Fixed SmallFloat64 encoding algorithm:
   - Rotate left 1 (move sign to LSB)
   - Subtract 0x7000000000000000 offset
   - Shift left 3 and add tag 5

7. Cleaned up debug output from Interpreter.cpp

8. Fixed TaskbarMorph/MenubarMorph visibility:
   - System morphs (MenubarMorph, TaskbarMorph) have forced standard bounds
   - MenubarMorph: full width, offset below macOS title bar
   - TaskbarMorph: full width at bottom
   - These are set regardless of actual slot values (layout may not be initialized at startup)

9. Added basic text rendering:
   - 5x7 bitmap font for printable ASCII (32-126)
   - Text extracted from slots 5-11 (different morphs store text in different slots)
   - Auto-contrast: white text on dark backgrounds, black on light
   - Text morphs detected by class name containing: String, Label, MenuItem, Item

10. Added Retina display support:
    - Detects Retina by checking if display width > 1500px
    - Scales coordinates 2x for Retina (menu bar offset, morph bounds)
    - Font scale: 3x on Retina, 2x on standard displays
    - MenubarItemMorph bounds scaled to match display resolution

WORKAROUND IMPLEMENTED:

- Menu bar click detection based on y-coordinate and x-position
- Dropdown menu rendering when menu is selected:
  - Light gray dropdown box appears below clicked menu
  - Tries to extract menu item text from Pharo menu structures
  - Falls back to "(Menu not loaded)" placeholder if structure not found
  - Click outside menu or click same menu to close

CLICK DETECTION FIX (2026-01-10):
**ROOT CAUSE**: Coordinate system mismatch!
- Touch events from iOS are in POINTS (logical pixels)
- Display surface and menu bar detection were in PIXELS (physical pixels)
- On Retina: 1 point = 2 pixels
- Touch at y=40 points was compared to menu bar at y=56-100 pixels → NEVER MATCHED

**FIX**: Scale touch coordinates to pixels before menu detection:
```cpp
int x = event.arg1 * scale;  // Convert points to pixels
int y = event.arg2 * scale;  // Convert points to pixels
```
Now touch at y=40 points → y=80 pixels (on Retina), which IS in menu bar range.
