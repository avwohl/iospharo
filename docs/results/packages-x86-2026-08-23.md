# Package tier, x86_64, 2026-08-23 — parity with arm64, and the two old gaps closed

Same script (`scripts/package-tests-selfhosted.sh`), same base image as the
arm64 run in `packages-arm-2026-08-22.md`, `build-x86/test_load_image` under
Rosetta, on an otherwise idle machine.

Run with the timeouts sized for x86, which is the whole reason the previous
x86 numbers looked worse than they were:

    PER_CLASS_TIMEOUT=420  LOAD_TIMEOUT=1800  TEST_TIMEOUT=1800

354 classes on both, and the two architectures differ by **four tests, all of

## The two gaps that are now closed

**XMLParser loads on x86_64.** It previously recorded

    XMLParser  load rc=0  54s  image=52MB DID-NOT-PERSIST

and was written up as "loads on arm64 and not on x86_64". This run:

    XMLParser  load rc=0  471s  image=1260MB grew
    XMLParser  test rc=0  391s  159 classes, 6354 pass, 0 fail, 5 err

**PolyMath is exactly arm64's 1448.** The old 59-test gap was
`PER_CLASS_TIMEOUT` sized for arm64: `PMArbitraryPrecisionFloatTest` needs
186 s on Rosetta against the old 180 s bound, and its expiry cost 57 passes.
With 420 s it answers what arm64 answers, and `PMKDTreeTest`'s 2-test
difference is gone too — 1448/2/18 on both arches, identical.

## The one real divergence: five `testAttributeDefaultValue*` errors

    arm64   XMLParserTest  190 ran, 189 passed, 1 error
              E: testAttributeDefaultValueEntities

    x86_64  XMLParserTest  190 ran, 185 passed, 5 errors
              E: testAttributeDefaultValueEntity
              E: testAttributeDefaultValueEntities
              E: testAttributeDefaultValueIDRef
              E: testAttributeDefaultValueIDRefs
              E: testAttributeDefaultValueNmtokens

One coherent family — DTD attribute default values with typed tokens — and
arm64's single error is a strict SUBSET of x86_64's five. That shape says one
root cause with architecture-dependent extent, not five unrelated flakes, and
unlike the intermittent `cull:` DNU it reproduced on every sweep.

This also answers the question `scripts/package-tests-selfhosted.sh`'s header
has carried since 2026-08-19 — "which 5th XMLParserTest case errored on x86"
— which counts alone could not answer. It is these five, by name.

`KeyNotFound: 'Fuel-Core-Tests'`. The 19 passes are the Fuel already in the
base image. Note the load was NOT flagged `CLONE-FAILED`, i.e. there was no

a clone problem.
