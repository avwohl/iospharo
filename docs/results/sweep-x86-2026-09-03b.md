# x86_64 full SUnit sweep with the storm guard, 2026-09-03

`scripts/sunit-sweep.sh` with `./build-x86/test_load_image` run IN PLACE (not a
copy -- that tree stages ~200 dylibs), `SUNIT_TIMEOUT_MULT=2`, same prepped
image and baseline environment as the arm64 run.  41 batches, **rc=0 on every
one**.

## Totals, against the same day's arm64 run

    arch      classes   PASS   FAIL  ERROR  SKIP  TIMEOUT
    arm64       2043    27812    18    28    182     3
    x86_64      2083    27810    20    24    180     8

(The class counts differ by the two classes each run loses to the `Total:`
splice -- a different two on each arch, because which test times out is
timing-dependent.)

## No codegen divergence between the arches

Fifteen classes out of 2043 differ, and every one of them has a non-codegen
explanation.

**x86-only, all timing or environment:**

    IntegerTest                 1 TIMEOUT   Rosetta runs ~2x slower
    RBBrowserEnvironmentTest    1 TIMEOUT   testVariableEnvironmentInstVars
    TraitMCDefinitionsTest      1 TIMEOUT
    ZnHTTPSTest                 1 TIMEOUT   testTransfers
    ReleaseTest                 3 T vs 1 T
    RSSequentialAnimationTest   1 ERROR     "Time up" -- a wall-clock assertion
    SpJobListPresenterTest      1 FAIL      "Got 84 instead of 100" -- wall-clock
    TFFunctionCallTest          1 ERROR     'w64Convention' not in libTestLibrary
    TFUFFIDifferentCalling...   1 ERROR     same Windows-only symbol
    TraitTest                   1 FAIL      testTraitsUsersSanity

`SUNIT_TIMEOUT_MULT=2` already compensates for Rosetta, and five of these still
land on the bound; they are the slowest cases in the suite.  The two
`w64Convention` errors are a symbol the test dylib does not export -- on arm64
the same cases report SKIP instead, which is a difference in the test's own
platform handling, not in generated code.

**arm-only:**

    LibTTYTest        5 ERROR   the copied-VM dylib artifact -- x86 ran the
                                binary in place and passes 5/5, which confirms
                                the diagnosis exactly
    RSRoassalTest     1 ERROR   defect #27, the ByteSymbol mis-dispatch; x86
                                clean, consistent with it being timing-flaky
    TKTWorkerTest     2 E vs 1  flaky worker timing
    TonelWriterV1Test 18 P vs 19

**The storm is arm64-only, and confirmed so.**  `CANNOT-RETURN-STORM` fires
once in the arm64 sweep and zero times in the x86_64 one; `DEAD-SENDER` is 4
against 1.  x86_64 has never reproduced defect #23.

## Conclusion for the "x86 and arm" half of the goal

28043 arm64 tests and 28022 x86_64 tests, and after attribution there is no
test that fails on one arch because of what the JIT emitted for it.  The
remaining arch-specific entries are a slower machine, two wall-clock
assertions, a symbol the test dylib lacks, and one harness mistake of mine.
