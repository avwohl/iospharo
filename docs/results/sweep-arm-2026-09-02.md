## Two classes were dropped by a write splice in the runner — FIXED

`MCSmalltalkhubRepositoryTest` and `TKTWorkerPoolTest` each timed out, and
each lost its `Total:` line into the middle of the watchdog's verdict:

    === MCSmalltalkhubRepositoryTest ===
      RUN: testVersionFromFileNamed
      TIMEOUT: testVersionFromFileNamed (exceeded 80s)
        WD-CLOCK now=Total: 1 P:0 F:0 E:0 S:0 T:1

Every offline aggregator anchors on `^Total:`, so both classes vanished from
the class count and their 10 tests from the totals.  The cause is in
`run_sunit_tests.st`: the P60 watchdog set `testDone := true` **before**
printing its verdict, so the P80 runner main woke out of its poll loop,
wrote the class summary into the half-written line, and then suspended the
watchdog on the "clean up watchdogs" path — which is why the rest of the
`WD-CLOCK` line never appears at all.

Fixed in the `scripts/pharo-headless-test` submodule: the verdict is composed
into a String and written with one `nextPutAll:`, and `testDone` is published
only after the flush.  The kill of the runaway test still happens first, so
the 2026-07-06 orphan race the old ordering existed to prevent stays
prevented.

## One batch died of a Context storm and took 39 classes with it

Batch 1901-1950 (`rc=134`) ran 11 of its 51 classes — `TimespanDoTest`
through `TonelWriterV3Test` — and then exhausted the 12 GB old space:

    [VM] FATAL: old space exhausted during scavenge tenure
    [HEAP-CENSUS] 47437613 objects, 12313 MB total
    [HEAP-CENSUS]  33363299 objs 11725994 KB  Context
    [HEAP-CENSUS]   6656491 objs   364026 KB  Error
    [HEAP-CENSUS]   6664295 objs   312344 KB  FullBlockClosure

Same signature as the storm that killed batch 601-650 on 2026-08-22 and the
same shape as the open "Monticello runaway" item in `docs/WIP.md`.  The ratios
are the useful part: 6.66M `Error`s to 6.66M `FullBlockClosure`s is 1.00, and
33.4M `Context`s to `Error`s is 5.01 — one handler block and about five live
frames per level of an unbounded recursion in which every level signals an
Error and catches it.  Nothing is being freed because the recursion never
unwinds, so every level's frames and its Error stay reachable.

**The missing classes are the trait tests.**  The batch ran indices 1901-1911
(`TimespanDoTest` .. `TonelWriterV3Test`) and died on 1912; batch 1951 starts
at `UndefinedPackageTest`.  Enumerating every class with methods in this
image's `.sources` between those two names gives 41 `*Test`/`*TestCase`
classes, which matches the 39-40 that never ran, and 27 of them are `Trait*`:

    TraitAbstractTest ... TraitWithSlotsTest        (27 classes)
    TrueTest, Tutorial*Test (3), UDPSocket*Test (2),
    UUID*Test (3), Undeclared/Undefined*Test (4)

So the storm starts at or just after the first concrete trait test.  **Stock
Cog runs all 27 of them clean — 270 tests, 0 F, 0 E, in seconds**
(`cog-trait-baseline.txt` beside this report, Cog v10.3.9 x86_64 under
Rosetta), so the storm is ours.  Filed as defect #23.  That
matters beyond naming it: `docs/vm-compat-bugs.md` has carried
"`TraitTest` — Cog 54 P / 0 F / 0 E, ours errors, not yet drilled" since
2026-06-01, and today's other newcomer, `OCClassBuilderTest`, also fails on a
**trait composition**.  Re-running 1901-1950 is queued behind the x86_64
sweep, because every SUnit runner invocation reads and writes the same `/tmp`
paths.

`TraitTest` is in that missing range, so its absence from the residual below
is "did not run", not "now clean".

The log also settles LEAD 19 in `docs/vm-compat-bugs.md`: the low-space
circuit breaker meant to stop exactly this printed **nothing**.  It was
sampling the threshold on a bytecode counter while old space drains in
eden-sized (22 MB) tenure steps against a 400 KB threshold, so it could only
fire 1.8% of the time.  Fixed the same day — see `docs/changes.md`.

Batch 1801-1850 shows `rc=124` (hit the 1800 s wall) but reported all 51
classes and the completion marker, i.e. it finished the tests and was killed
during shutdown.  Its results are in the totals.

## `ReleaseTest>>testUnknownProcesses` changed cause, and the new one is ours

On 2026-08-23 this failed with `MessageNotUnderstood:
DefaultExecutionEnvironment >> #watchDogProcess` and was filed as an image
bug.  In this run it fails differently:

    FAIL: testUnknownProcesses
      Found unknown processes: 'CommandLine handler process':'a Process in
      SessionManager>>snapshot:andQuit:

That is the prep step showing up in its own image.  `12ad7265` moved the
runner prep onto our VM ending in `Smalltalk snapshot: true andQuit: true`,
which is executed *by* the command-line handler process — so the saved image
resumes with that process parked inside `snapshot:andQuit:`, and a test whose
whole job is to enumerate unexpected processes finds it.  A harness artifact
of the current prep, not a VM defect, and the cheapest fix is to snapshot
from a process the handler is not holding.
