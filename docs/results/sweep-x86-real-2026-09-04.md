# Full SUnit sweep on REAL x86_64 Linux, 2026-09-04

The first complete 2047-class sweep of this VM on native x86_64 hardware — not
Rosetta.  AWS `m6a.4xlarge` spot (`i-069e3881670b0cac0`, us-east-2), Ubuntu
24.04, tree built on the box, fake-GUI-prepped image, `scripts/aws/x86-gui-sweep.sh`
with per-batch S3 checkpointing.

It ran as two attempts against one `RUN_ID`.  The first box was reaped at
index 500; the second RESUMED from the S3 checkpoint at index 501 rather than
restarting, which is the first real use of `START_AT` earning its keep.

The 12 x86-only TIMEOUTs are a bound being hit, not a computation going wrong.
Of the 7 x86-only FAIL/ERRORs, the shapes that carry their own explanation are
`SpJobListPresenterTest` (a wall-clock percentage: "Got 72 instead of 100"),
`StFileBrowserOpenTerminalCommandTest` (the terminal command differs between
Linux and macOS), `ZdcPluginSSLSessionTest` (wants a certificate file that is
not there), and the two Spec layout/selection tests (font metrics and GUI
event ordering under the fake GUI).  `LinkInstallerTest`'s "Leaked metalinks"
is the one worth a second look.

## Two things this settles that the Rosetta sweep could not

**The threaded-FFI batch is genuinely fixed.**  Batch 1801-1850 — the one that
used to burn the whole 1800 s `PER_BATCH_TIMEOUT` on both arches (defect #26)
— ran `rc=0` in **137 s** on real hardware.

**The fake-GUI `KeyboardKeyTest` wedge is macOS-specific.**  Batch 651-700, the
batch that costs 20 of 51 classes to a wedge on this Mac, ran `rc=0` in 126 s
here.

## The rc=137 batches are the sweep's own early kill, and they cost nothing

Roughly a third of batches came back `rc=137`.  That is `sunit-sweep.sh`
killing a VM that has already written `/tmp/sunit_run_completed.txt` and is
still alive `SHUTDOWN_GRACE=30` s later.  **Every one of them wrote all 51
class totals and `*** BATCH COMPLETED`**, which is why the sweep still reports
2047 classes.  What the VM is doing in that window is analysed as defect #29:
it is not hung, it is running the Opal compiler at ~8e9 bytecodes with a full
JIT code zone, and `primitiveQuit` is never reached.

## Caveat on `TraitFileOutTest`

Its 2 ERRORs here are the working-directory artifact of defect #28, not a VM
defect: this sweep ran before `RUN_FROM_IMAGE_DIR` was defaulted on.  A sweep
on the current `sunit-sweep.sh` should show it clean.
