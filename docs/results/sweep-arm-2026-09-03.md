## Two things in this run are the harness, not the VM

**LibTTYTest's 5 errors are a copied VM.**  The sweep runs a copy of the binary
so a rebuild cannot change it mid-run, and the copy left `libtty.dylib` behind:
`SymbolNotFoundError: Could not find symbol named: #tty_spawn`.  Same shape as
the x86-loses-libgit2 note.  Both dylibs are now staged beside the copies.

**Two classes are still lost to the `Total:` splice.**  `RSViolinPlotTest` and
`TKTCommonQueueWorkerPoolTest` have no `^Total:` line because the watchdog
verdict swallowed it:

    TIMEOUT: testWorkerPoolWorkersProcessesAreTerminated... (exceeded 8Total: 7 P:6 ...

That is fixed in the `scripts/pharo-headless-test` submodule and this image was
prepped BEFORE the fix.  Re-prepping recovers both classes; the fix is not in
question, the image is.
