## Key Wins

1. **IC probe default-on** is the single biggest win.  The chain-loop
   bypasses the J2J trampoline conversion when the probe is on, which
   was the source of the `sortStructs:into:` MUSTBOOL cascade.
   Throughput on sends: 59M → 75-86M/sec.

2. **bitAnd: / bitOr: / `*` in JIT** lets ~5-10% more methods real-emit
   instead of compiling as stubs.  Big wins on bench loops that use
   any arithmetic beyond +/-/comparisons.

## Variance Note

Bench variance is high — runs of the same config can swing 3-4× on
the iterator-heavy benchmarks (`collect`, `sieve`).  JIT compile
ordering is non-deterministic and dictates which methods are hot when
each phase runs.  `tinyBenchmarks sends/sec` is the most stable
metric and the only one I'd quote with confidence.

## Things Tried But Reverted

- 2-slot polymorphic IC probe — high variance, didn't pan out.
- `canJITActivate` stub-skip — made the stub-trip path slower for
  complex callees (`collect` regressed reliably).
- Conditional jumps default-on — `sieve` 3× faster but
  `tinyBenchmarks` bytecode throughput dropped 30%; unrelated
  downstream issue.
- `PHARO_ASMJIT_T1_FORCE_RESUME_FOR_SENDS=1` — fuzzer regression even
  with `state.method` synced.  Deeper trampoline desync still
  un-rooted.

## Knobs Available

- `PHARO_T1_NO_IC_PROBE=1` — revert to old probe-off behavior
- `PHARO_T1_NO_J2J_TRAMP=0` — re-enable the broken trampoline path
  (only useful for bisection)
- `PHARO_ASMJIT_T1_ENABLE_JUMPS=1` — enable conditional-jump emit
  (known-buggy; some benches faster, others worse)
