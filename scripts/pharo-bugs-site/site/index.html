Pharo test defects

How these tests extend the Pharo CI

What the Pharo CI runs

  • The CI of pharo-project/pharo builds the image and runs all its SUnit tests (test '.*') with the stock VM on Linux, macOS and Windows, 64-bit, and the command-line tests (Jenkinsfile, runTests.sh).
  • The CI of pharo-project/pharo-vm runs the VM unit tests (VMMakerTests, Slang-Tests), then the SUnit tests of the image on the new VM. A failure of the image tests marks the build, but does not stop it (Jenkinsfile).
  • Both set PHARO_CI_TESTING_ENVIRONMENT, and some tests skip when it is set (see below).

What we add

  • A second VM. Each test runs on stock Cog v12.0.6 and on iospharo, a VM written separately (C++, with a JIT for arm64 and x86_64). A test that fails the same way on two VMs points at the image, the test or the package, not at one VM. The platform is macOS arm64.
  • Skips and expected failures are failures. A test that skips or carries the expected-failure mark is work to do here, not a pass. The CI does not report these tests as failures.
  • The whole SUnit suite of Pharo 14 (build 791): 39465 tests in 2160 classes, each parameter set of a parametrized test counted once. Six classes that need a display (135 tests) also run in an interactive session. The Pharo 13 suite (28077 tests) ran too.
  • Repetition. The full suite ran 22 times on 2026-11-17 (13 times on iospharo, 9 times on Cog with our Cog changes). Tests that failed at random ran in loops of 600 to 3000 runs. The loops found races in the image that one CI run does not show: the TaskIt worker pool (83 failures in 600 runs before the fix, 0 in 3000 after), the wake-ups of AtomicSharedQueue, and the uninstall of an object-specific MetaLink, which depends on the order of a set.
  • Packages. 200 maintained packages with tests, from the Soogle index of public Smalltalk code: of 26,876 Pharo repositories, 528 had a push in the last year, 318 had a BaselineOf and tests, and 200 were chosen for variety (a limit for each GitHub organization). Stock Cog loads each package into Pharo 14, then the two VMs run its tests. Rows 1 to 163 ran: 155 packages loaded, with 46,419 tests. The package tests found defects in the image that the image suite does not cover: RBNamespace>>renameClass:to:around:, Duration>>asDelay and the equality of ZnUrl.
  • Stock Cog. The runs found 11 defects in stock Cog. 9 have a change on a local branch of pharo-vm, built and tested; 2 are open (segmentation faults with no known cause). See the Cog section.

Tests that the Pharo CI accepts as known failures

  • 220 tests of Pharo 14 build 791 do not pass, the same on the two VMs: 170 skips, 49 tests with the expected-failure mark and 1 failure (ZnClientTest>>testQueryGoogle, which searches the Google result page for pharo.org). 132 of them pass with a fix of the image or of the test. 4 more pass with a fix of the image and a Cog change. 56 cannot apply on macOS arm64: fixtures, Windows, 32-bit. 28 need a display. The section "Defects in the Pharo 14 image" has a page for each group.
  • 8 tests skip when PHARO_CI_TESTING_ENVIRONMENT is set (TestCase>>skipOnPharoCITestingEnvironment). Our runs do not set the variable, so the tests run: RandomTest>>testUnixRandomGeneratorSeed, AllocationTest>>testOneGBAllocation (on Windows only), AllocationTest>>testOneGWordAllocation, OmDeferrerTest>>testExecuteOnceAfterScheduling, OmDeferrerTest>>testExecuteWithoutDelay, WeakAnnouncerTest>>testNoDeadWeakSubscriptions, DebugPointTest>>testTranscriptDebugPoint, TKTNewProcessTaskRunnerTest>>testNewProcessTaskRunnerRunsInNewProcessEveryTime (fails at random: page). In our 6 saved full runs of 2026-11-17, 7 of the 8 pass every time; the TaskIt test failed once.
  • The VM CI removes ReflectivityControlTest>>testAfterSequence before its run, because the test stopped the VM (patchPharoPreTests.st, pharo issue 11745). The test passes in our 6 saved full runs, on iospharo and on Cog with our Cog changes.

How the results were made: each test ran on two VMs, the stock Cog VM and iospharo, a second Pharo VM (a C++ reimplementation with a JIT for arm64 and x86_64). A test that fails the same way on two VMs points at the image, the test or the package, not at one VM. In the records, ours and our VM mean iospharo. Stock Cog is the Pharo VM v12.0.6 (arm64), macOS arm64. Patched Cog is stock Cog with the Cog changes of the Cog section. The image is Pharo 14, build 791. A sweep runs the full test suite of the image (39465 tests). The full list of tests is in nonpassing-tests-2026-11-18.tsv.

The 220 Pharo 14 tests of 2026-11-17: 132 fixed by an image fix, 4 fixed in the image but stock Cog also needs a Cog change, 56 cannot apply on macOS arm64 (12 of them with an open point), 28 need an interactive session. 18 more tests came up during the work, and 7 tests failed at times in earlier runs.

About the Upstream column: the Pharo 14 image is built from pharo-project/pharo and from projects that BaselineOfPharo loads at a fixed version: Spec v2.0.6, NewTools v0.11.0, NewTools-DocumentBrowser v1.1.1, Microdown v2.11.0, Roassal v1.7.7 (which loads Geometry v1.2.1). A fix in such a project gets into the image when Pharo moves the version. The development branch is Pharo15 (Microdown: dev, Geometry: master); the fixes were measured on Pharo 14 build 791.
