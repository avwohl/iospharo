Record

  • Defect of our manifest: the row loaded the baseline PharoMisc only. That baseline has one class and no test. The repository has one baseline for each of its projects.
  • Repair: the row now loads nine baselines (PharoMisc, StateMachine, Concurrency, BooleanExpressions, BaselineAnalyzer, CodeMetrics, LightweightObserver, PharoExtra, SimpleMiddleware). Not in the row: Tasks, NetworkExtras and EasyUI, whose baselines name the repository without its Pharo directory.
  • State before the repairs: 225 tests, 160 pass, 41 fail, 24 errors, the same on the two VMs. The branch of the package is pharo12: the code is for Pharo 12.
  • Result with fixes/bouraqadi-pharomisc.st: 225 of 225 pass on the two VMs.
  • CodeMetrics (CmCodeAnalyzerTest, 5 errors): CmCodeAnalyzer asks the global SystemOrganizer for category names and for the classes of a category. Pharo 14 has no such global. The two methods now read the package tags (PackageTag>>categoryName). The tests need a category with no class, which a Tonel repository cannot hold, so setUp makes the tag and tearDown removes it.
  • LightweightObserver (57 tests). The fixes file has a port to Pharo 14:
    • LoSubject class wrapped each method that writes an instance variable through the Pharo 12 hook ClassDescription>>addAndClassifySelector:withMethod:inProtocol:. Pharo 14 installs a method with addSelectorSilently:withMethod:, and the port puts the hook there.
    • The source of a wrapper method is the source of its basic method. The Pharo 14 compiler keeps the generated source in the #source property of the wrapper, and a file-out of the class then had the generated source (testFileOutIngnoresGeneratedMethods).
    • The tests made their classes with the ST80 class creation messages of ClassFactoryForTestCase. They now use the class builder.
    • Array>>asSubject sends becomeForward: to the receiver. A literal array is read-only in Pharo 14, so the method makes the receiver writable first.
    • LoSubjectSortedCollection>>addLast: came from a trait and called SortedCollection>>addLast:, which is shouldNotImplement.
    • Three presenter classes are Spec 1 code. The port has Spec 2 versions.
  • SimpleMiddleware (SmSingleMiddlewareTest>>testCommunication, ConnectionClosed after 8 ms): the test uses the default port of SmServer, 54321. On the test machine another program listens on 127.0.0.1:54321. SmServer listens on the wildcard address with the address reuse option, and macOS lets that bind go through. The proxy connects to 127.0.0.1:54321, and the other program gets the connection and closes it. The test now asks the system for a free port. The change for the package: do not use a fixed port in a test.
  • Three more baselines (Tasks, NetworkExtras, EasyUI) name the repository as github://bouraqadi/PharoMisc:pharo12, and the code is in the directory Pharo. patches/bouraqadi-pharomisc.patch adds /Pharo to that repository line in the three baselines, and the row now loads them: 361 tests.
  • NetworkExtras, multicast sockets. 13 tests failed on our VM only. They showed a defect of our VM: the socket option primitives knew 6 option names and gave a false success for each other name (the iospharo defect list). The tests also showed these defects of the package:
    • Two sockets on one port. The tests make the sender as a second NeMulticastSocket on the port of the receiver, and NeMulticastSocket>>group:port: always binds the port. The stock VM does not report the failed bind of the second socket (scripts/cogdiff/socket_bind_in_use.st), so the sender stayed unbound there with no error, and the tests passed. Our VM reports Address already in use. The fixes file adds a socket that only sends (NeMulticastSocket class>>sendToGroup:port:: no bind, no group membership), and the tests use it for the sender. A first repair (the reuse options before the bind) was wrong: three sockets then listen on one port, and the system gives a unicast datagram to only one of them.
    • NeUdpUnicastSocketTest>>testCloseWhileReceiving sends a datagram, closes the receiver, and expects that the reader gets no data. The datagram is in the buffer of the receiver before the close, so the reader can get it. The test passed on the stock VM in each run and failed on our VM in some runs. The test now sends no datagram: a reader that waits gets ConnectionClosed when the socket closes.
    • NeMulticastSocketTest>>testInterface was an expected failure that ends with self fail: #todo. The fixes file has the finished test and the two accessors of IP_MULTICAST_IF that the test needs.
  • Tasks, TkThreadTest>>testPeriodFixedDuration: the cause is a defect of the Pharo image, Duration>>asDelay. See pharo-image-repairs-2026-11-17.md.
  • Result of the row with 12 baselines: 361 of 361 pass on the two VMs.
  • Open, in stock Cog: a segmentation fault in its garbage collector. The fault came with the first repair of the multicast tests (the reuse options, three sockets on one port). Stock Cog stopped in TkThreadTest>>testFinalization, in 3 runs of 3. The fixes file of commit 5053c46f gives that state. With the repair of this section the fault does not show. The cause is not known.

"PharoMisc, LightweightObserver (append to the entries of this file).

G1. LoSubject class used the Pharo 12 hook ClassDescription>>addAndClassifySelector:withMethod:inProtocol: to wrap each method that writes an instance variable (wrapper method with the old selector sends the event, the user method is kept under basicSubjectMethod_<selector>).  Pharo 14 never sends that message: every installer ends in Behavior>>addSelectorSilently:withMethod: (OCMethodInstaller>>addAndClassifyMethod:into:), so no wrapper exists and no observer fires.  The hook now overrides addSelectorSilently:withMethod: in LoSubject class, updates methodDict and localMethodDict, and the old compiler calls (failBlock:, compile, putSource:withPreamble:) are replaced.  A wrapper answers the source pointer and the source of its basic method, so Behavior>>compile:from: keeps the user source through every recompilation.  LoSubject initialize at the end wraps the methods that were loaded before the hook existed.

G2. LoSubjectAutomaticCodeGenerationTest used ClassFactoryForTestCase>>silentlyNewSubclassOf:instanceVariableNames:classVariableNames: and newSubclassOf:..., the ST80 subclass:instanceVariableNames:... message and Class>>fileOutOn:.  Pharo 14 has silentlyMake:, make:, update:to: (with ClassFactoryForTestCase environment:) and the Fileouter class.  The tests keep every assertion; only the way to make or change the class and to file it out changes.

G3. Array>>asSubject sends becomeForward: to the receiver.  The receiver of LoArrayAutomaticEventGenerationTest>>testReset is a literal Array, and Pharo 14 compiles literals as read-only (beReadOnlyLiteral).  Primitive 72 refuses a read-only receiver with 'no modification' on Cog and on our VM, so the receiver is made writable first.

G4. LoSubjectSortedCollection got addLast: from a trait whose super is SortedCollection>>addLast:, which is shouldNotImplement, so the tests that append at the end fail.  SortedCollection>>addAll: adds with addNoSort: and sorts once, so add: is never sent and no event is dispatched.  addLast: now appends without sorting and sends the add event, and addAll: sends add: for each element.

G5. LoDicePresenter, LoDiceListPresenter and LoDiceAdderPresenter are Spec 1 classes (ComposablePresenter, DynamicComposablePresenter, SpecLayout).  Pharo 14 has only Spec 2, so the three classes are not created at load and LoDiceUiTest reads undeclared variables.  The classes are made again with Spec 2 and the observer logic is unchanged.  Lowest confidence: Spec 2 messages were not checked against sources."

"G1: source of a wrapper method comes from its basic method."
add value: #LoSubjectSupportMethod value: #basicMethodOrNil value: 'subject support' value:
'basicMethodOrNil
	"The basic method that a wrapper method calls.  Answers nil when the receiver is itself the basic method, or when there is none."

	| basicMethod |
	self methodClass ifNil: [ ^ nil ].
	basicMethod := self methodClass methodDict
		at: (LoSubject basicMethodSelectorFrom: self selector)
		ifAbsent: [ ^ nil ].
	^ basicMethod == self
		ifTrue: [ nil ]
		ifFalse: [ basicMethod ]'.

add value: #LoSubjectSupportMethod value: #sourcePointer value: 'source code management' value:
'sourcePointer
	"A wrapper method has no source of its own: it answers the source pointer of its basic method.  Behavior>>compile:from: copies this pointer to the new method, so the user source survives a recompilation."

	| pointer basicMethod |
	pointer := super sourcePointer.
	pointer = 0 ifFalse: [ ^ pointer ].
	basicMethod := self basicMethodOrNil.
	^ basicMethod
		ifNil: [ 0 ]
		ifNotNil: [ basicMethod sourcePointer ]'.

add value: #LoSubjectSupportMethod value: #sourceCodeOrNil value: 'source code management' value:
'sourceCodeOrNil
	"The source of a wrapper method is the source that the user wrote, which the basic method holds.  The #source property of the wrapper (set by the Pharo 14 compiler, OpalCompiler>>generateMethod) is the generated wrapper source and must not win: the file-out of a class reads sourceCode."

	| basicMethod |
	basicMethod := self basicMethodOrNil.
	^ basicMethod
		ifNil: [ super sourceCodeOrNil ]
		ifNotNil: [ basicMethod sourceCodeOrNil ]'.

add value: #LoSubjectSupportMethod value: #sourceCode value: 'source code management' value:
'sourceCode
	"Never decompile a wrapper method: its bytecode shows the generated code.  Without any source, the decompiled basic method is the code of the user."

	| basicMethod |
	^ self sourceCodeOrNil ifNil: [
		basicMethod := self basicMethodOrNil.
		basicMethod
			ifNil: [ super sourceCode ]
			ifNotNil: [ basicMethod sourceCode ] ]'.
