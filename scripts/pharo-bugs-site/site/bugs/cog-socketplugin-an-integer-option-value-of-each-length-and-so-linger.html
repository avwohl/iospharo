Record

  • Defect 1: sqSocketSetOptions... reads an integer only from a value of sizeof(int) characters or less. The image gives the value as a string. Socket>>setOption: 'SO_RCVBUF' value: 65536 goes to setsockopt as the 5 characters 65536, and the system reads the first 4 of them as the int. On macOS the buffer becomes 8 MB.
  • Defect 2: SO_LINGER is in the option table, but setsockopt gets one int for it, and the system needs a struct linger. The primitive fails, so the image cannot set the option.
  • Measurement (scripts/cogdiff/socket_options.st, 72 option calls on a UDP socket and on a TCP socket): the stock VM and our VM differ in these 4 lines only.
  • Change: a value that reads as an integer is an int of each length. For SO_LINGER the value is the linger time in a struct linger, 0 sets the option off, and the get primitive answers the linger time.
  • Test (2026-11-17, macOS 27, arm64): with the change, the patched Cog and our VM give the same answer for each of the 72 calls of the script.
  • Not tested: Windows and Linux.

Fix

From: Aaron Wohl

Subject: [PATCH] SocketPlugin: an integer option value of each length, and
 SO_LINGER as a struct linger

sqSocketSetOptions read an integer only from a value of sizeof(int)
characters or less.  Socket>>setOption: 'SO_RCVBUF' value: 65536 went to
setsockopt as the 5 characters '65536', and the system read the first 4 of
them as the int: the buffer became 8 MB on macOS.  A value that reads as an
integer is now an int of each length.

SO_LINGER is in the option table, but setsockopt got one int for it and
answered EINVAL, so the option could not be set.  The value is now the
linger time in a struct linger (0 sets the option off), and the get
primitive answers the linger time.
