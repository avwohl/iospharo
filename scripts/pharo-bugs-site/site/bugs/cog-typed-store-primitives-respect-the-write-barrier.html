Record

  • Defect: the primitives 615 to 629 (primitiveStore*IntoBytes) and primitiveFFIIntegerAtPut do not test the receiver for immutability. A typed store into a read-only ByteArray changes the bytes, and the VM signals no ModificationForbidden.
  • Change: each primitive fails with PrimErrNoModification for a read-only receiver, as primitiveAtPut does. The JIT has machine code versions of the 32-bit and 64-bit stores. The machine code now leaves without a store when the receiver is read-only. Without that part, a store was blocked in the interpreter and went through after the JIT compiled the method.
  • Test (2026-11-17, a Debug build with the change): WriteBarrierTest gives 33 passes of 33 with the image fixes of this repository. The stock VM fails 4 of the 33: the two tests that upstream marked as expected failures (testMutateByteArrayUsingDoubleAtPut, testMutateByteArrayUsingFloatAtPut) and the two integer tests that this repository adds.
  • The image has a defect in the same path: TFFIBackend>>on:float64At:put: and on:float32At:put: test self (the backend) for read-only, not anObject. The image fix is in scripts/image-fixes/20-WriteBarrierTest.st.
  • Our VM had a related defect (primitiveFFIIntegerAtPut wrote into a read-only object). This repository has the fix for that defect.

Test

"Run in a Playground of a Pharo 14 image."
g := ByteArray new: 8.  g beReadOnlyObject.
[ g float64AtOffset: 0 put: 2.5 ] on: ModificationForbidden do: [ :e | e return: #forbidden ].
g printString.
"Stock Cog: the store changes g to #[0 0 0 0 0 0 4 64].  With the change: ModificationForbidden, and g stays all zero."

21-write-barrier-integer-stores.st (download)
"Write barrier for the typed integer stores into a ByteArray (2026-11-17).

The typed store primitives 615-627 fail on a read-only ByteArray on our VM.
The fallback of each accessor goes through ByteArray>>integerAt:put:size:signed:
to the named primitive primitiveFFIIntegerAtPut.  That primitive wrote the
bytes of the read-only object on our VM (fixed in the VM on 2026-11-17: the
primitive now fails).  Stock Cog writes the bytes in the primitives 615-627
themselves (docs/upstream has the Cog change).

W1. With the two VM changes the fallback ended in PrimitiveFailed.  A store
into a read-only object must signal ModificationForbidden, as at:put: does, so
that a handler can make the object writable and retry.  The retry selector is
the index-based accessor of the same size and sign.

W2, W3. WriteBarrierTest has tests for at:put:, doubleAt:put: and floatAt:put:
on a read-only ByteArray, and none for an integer store.  Two tests with the
form of testMutateByteArrayUsingDoubleAtPut."

fix value: #ByteArray value: #integerAt:put:size:signed:
	value: [ :source | (source includesSubstring: 'isReadOnlyObject') not ]
	value:
'integerAt: byteOffset put: value size: nBytes signed: aBoolean

	self isReadOnlyObject ifTrue: [
		| selectors |
		selectors := aBoolean
			ifTrue: [ #( #signedByteAt:put: #signedShortAt:put: nil #signedLongAt:put: nil nil nil #signedLongLongAt:put: ) ]
			ifFalse: [ #( #unsignedByteAt:put: #unsignedShortAt:put: nil #unsignedLongAt:put: nil nil nil #unsignedLongLongAt:put: ) ].
		^ self
			  modificationForbiddenFor: (selectors at: nBytes)
			  index: byteOffset
			  value: value ].

	^ FFIBackend current
		  integerOfObject: self
		  at: byteOffset
		  put: value
		  size: nBytes
		  signed: aBoolean'.

cog-write-barrier-typed-stores.patch (download)
From 03d50c9754c3be0145864b0f815c0d1af15646e0 Mon Sep 17 00:00:00 2001
From: Aaron Wohl
Date: Tue, 17 Nov 2026 07:39:09 -0500
Subject: [PATCH] Typed store primitives respect the write barrier

The primitives that store a typed value into the bytes of an object
(primitiveStore*IntoBytes, 615 to 629) and primitiveFFIIntegerAtPut did not
test the receiver for immutability.  A store into a read-only ByteArray
changed the bytes, and no ModificationForbidden was signalled:

    g := ByteArray new: 8.  g beReadOnlyObject.
    g float64AtOffset: 0 put: 2.5.      "g is now #[0 0 0 0 0 0 4 64]"
    g uint32AtOffset: 0 put: 7.         "g is now #[7 0 0 0 ...]"

Each C primitive now fails with PrimErrNoModification for a read-only
receiver, as primitiveAtPut does.  primitiveFFIIntegerAtPut does the test
only for a store into the bytes of the receiver itself; a store through an
ExternalAddress goes to outside memory.

The JIT has machine code versions of these primitives
(genPrimitiveStore:intoBytesWith:needsToTrap:).  The machine code now leaves
without a store when the receiver is read-only, so the C primitive or the
fallback code of the method handles the case.  Without this part a store
was blocked in the interpreter and went through after the method was
compiled.

The image has two tests for this with the expected-failure mark
(WriteBarrierTest>>testMutateByteArrayUsingDoubleAtPut and
testMutateByteArrayUsingFloatAtPut).  With this change, and with the image
methods TFFIBackend>>on:float64At:put: and on:float32At:put: testing
anObject in place of self, the two tests pass.

Measured on macOS 27, arm64: after the change the two stores above leave g
all zero, also through unsignedLongAt:put: from compiled code.
