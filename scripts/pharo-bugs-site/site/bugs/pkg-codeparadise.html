Record

  • State before: 33 tests, 19 pass, 1 failure, 13 skips on the two VMs. The 13 are tests with self skip as their first statement.
  • A first repair took the skips out with a stand-in for the client environment. A run showed that it was wrong: the tests then failed on stock Cog, and one of them hung on our VM. That repair is gone.
  • The hang, measured:
    • CpClientCommunicator>>checkConnection with no URL calls reconnect, which fails inside a handler that takes each Error and answers nil, and calls checkConnection again. The recursion has no end.
    • The time limit of SUnit signals TestTookTooMuchTime, an Error. The same handler takes the signal when the signal comes inside it. In 200 trials the signal ended the test in 41 on stock Cog and in 13 on our VM.
    • Our VM then had a limit of 56000 frames for each process. Its error went into the same handler, a second one stopped the process with no unwind, and the run had no end. Since the deep recursion change of 2026-11-17 our VM has no such limit, and the test ends by the time limit as on stock Cog.
  • Repair (fixes/erikonbike-codeparadise.st), with no stand-in:
    • checkConnection does nothing when the communicator has no URL, and reconnect asks the client environment only when one runs.
    • 6 tests of CpCommunicatorTest run: the client comes from a helper, three tests make their Semaphore before the connection (a race), and setUp and tearDown stop the servers and close the clients.
    • 2 of them were stale: commit 0fb2f0a (2021) made "always reconnect" the default, and the tests assert the state with no reconnect strategy. They now set that state. Each assertion stays.
    • testLookAheadAt was stale since commit 9f09c7f moved the index of ReadStream>>lookAheadAt: by one. It uses the present index.
  • 7 tests cannot apply in a server image (not-applicable/erikonbike-codeparadise.txt, with the proof for each): 4 of CpClientEnvironmentTest and 3 of CpEncodeDecodeObjectTest. The code under test is the client side, which runs in a small image in the browser. The package refuses that code in an image with the server classes. Each of the 7 keeps its skip, with the reason as its text.
  • For the owner of the package: a reconnect that fails for a URL that is set still calls checkConnection again at once. And testSortedCollection passes with a stand-in client environment; it is in the list of 7 because the repair uses no stand-in.
  • Result, in a run from a new load: 26 pass and 7 skips on the two VMs; each skip is in the not-applicable file.

Fixes file (filed in after the load): erikonbike-codeparadise.st (download)
"ErikOnBike/CodeParadise (row 121).  Before: 33 tests, 19 pass, 13 skip, 1 fail.

A. The six tests of CpCommunicatorTest were disabled with 'self skip.' (comment:
   'safety checks prevent it').  They run a client and a server Communicator in one
   image.  They did not pass for six reasons; each is repaired where it is:
   1. CpClientCommunicator>>checkConnection reconnected also when the communicator
      never had an URL.  #reconnect calls #connectToUrl: nil, which fails, and
      #connectToUrl: ends in #messageChannel: nil, which calls #checkConnection
      again: endless recursion.  testClientSendBeforeConnection sends messages
      before #connectToUrl:, so it hit this and ran until the watchdog of the
      test runner stopped it.  (The package guards the creation of a
      CpClientCommunicator in a server image, 'deadlock issues'; this is a
      likely cause.)  Package code: with no URL there is nothing to reconnect to.
   2. CpClientCommunicator>>reconnect sent 'CpClientEnvironment current
      restartCommunication'.  Only a client has a ClientEnvironment; in a server
      image #current refuses.  Now #restartCommunication is sent when a
      ClientEnvironment is running (the real client: always).  Package code.
   3. Since commit 0fb2f0a (2021) a new CpClientCommunicator has the strategy to
      always reconnect (#initialize).  testConnectionStrategies and
      testSendWithReconnects test the state without a strategy ('Default no
      reconnect', 'Client is no longer connected'); they predate the commit.  The
      class comment says: without a strategy a lost connection is not restored.
      The tests now set 'reconnectStrategy: nil' and keep their assertions.
   4. Three tests made the Semaphore after the connection.  The handler process
      (priority highIOPriority) of the other side runs at once, finds the Semaphore
      nil and fails, and the signal is lost.  The Semaphore is made at the start.
   5. CpClientCommunicator class>>newForOwner: refuses in an image that has a
      CpServerCommunicator.  The tests build the client with #initializeWithOwner:
      (the code of CpCommunicator class>>newForOwner:) through a helper.
   6. All tests use port 1701.  A test that stops early left its ZnServer and its
      channels.  setUp and tearDown of the test class now stop them.
B. Seven tests need the client environment and keep their skip, now with a reason
   text: they cannot apply in a server image (proof in the .not-applicable.txt file).
C. CpReadStreamExtensionTest>>testLookAheadAt asserts the index of before commit
   9f09c7f (2021).  That commit moved the index by one in ReadStream>>lookAheadAt:
   and in its callers, and did not change the test.  The test now uses the index of
   the extension: 0 is the element that #peek answers, 1 the one after it, -1 the
   element that #next answered last.  No assertion is removed.

All entries are guarded on text that only the old source has."

# Tests that cannot apply in a server image.  One test for each line:
# Class>>selector.  A line that starts with # has the proof.
#
# CodeParadise runs a web application as two images: a server image (this one,
# Pharo 14, has CpServerEnvironment) and a tiny client image that runs in the
# browser (SqueakJS; docs/Implementation.md: "client-environment.image is a tiny
# Smalltalk image ... based on Pharo Candle ... no Compiler").  The classes
# under test below are client code.  By design the package refuses to run
# them in an image that has the server side classes (the comments say: "to
# prevent CompiledMethods from being installed" and "to prevent communicators
# from crashing the image"; the author skipped the tests for that reason).
#
# Proof 1: each test, with the skip taken out, in the unchanged package in this
# image (both VMs give the same text):
#   CpClientEnvironmentTest>>testInstallClass, testInstallMethod,
#   testInstallMethodWithClassVarAccess, testInstallMethodWithInstVarAccess:
#     Error: Creating ClientEnvironment instances on the server is temporarily
#     disabled because of deadlock issues
#     (CpClientEnvironment class>>current: "Smalltalk classNamed:
#     #CpServerEnvironment" is not nil)
#   CpEncodeDecodeObjectTest>>testCompiledMethod,
#   testCompiledMethodWithAdditionalMethodState:
#     Error: ClientEnvironment sent CompiledMethod to ServerEnvironment
#     (CpObjectDecoder>>decodeCompiledMethod: CpClientEnvironment isRunning)
#   CpEncodeDecodeObjectTest>>testSortedCollection:
#     Error: ClientEnvironment sent CompiledBlock to ServerEnvironment
#     (CpObjectDecoder>>decodeCleanBlockClosure: CpClientEnvironment isRunning)
#
# Proof 2: the client environment is a singleton of the client image.  With a
# stand-in for it (the class variable Current set, #current answering it; this
# is NOT in the repair, it is a measurement) the tests still do not pass,
# because the code under test expects the client image:
#   testCompiledMethod, testCompiledMethodWithAdditionalMethodState:
#     "Unknown type in decode stream".  CpObjectDecoder>>decodeCompiledMethod
#     makes the method with 'CompiledMethod basicNew: bytecodeSize + 4 header:'.
#     The 4 is the trailer size of the client image.  CompiledMethod trailerSize
#     is 5 in this image, so the decoder reads one byte too few and the next
#     literal starts at the wrong place.  With the trailer size of this image
#     the decode works, and the test still fails ('Encode/decode ... >>
#     #testCompiledMethod'): the decoded method is not equal to the original
#     (see the .md: compareMethod:to:).
#   testInstallMethod, testInstallMethodWithClassVarAccess,
#   testInstallMethodWithInstVarAccess: the same decoder error is swallowed by
#     CpClientEnvironment>>handleMessageReceived:, the method is not installed
#     (MessageNotUnderstood #temporaryMethod), and the ensure: block of the
#     test fails with KeyNotFound.  Also the cleanup of the tests makes an
#     endless recursion in this image: Class>>removeMethod: of the package
#     sends #removeInstanceMethod: while CpClientEnvironment isRunning, and
#     Behavior>>removeInstanceMethod: sends #removeSelector:, which in Pharo
#     14 sends #removeMethod: again.  (On the tiny image #removeSelector: does
#     not call #removeMethod:.)  The run of the endless recursion stopped
#     stock Cog with a segmentation fault (low space) once.
#   testInstallClass: the test calls 'Object subclass:instanceVariableNames:
#     classVariableNames:package:', which Pharo 14 does not have
#     (MessageNotUnderstood), and the decoder of a class builds the class with
#     the format of the client image.
#
# Open point for the owner: testSortedCollection PASSES on both VMs when the

# thing the repair rule forbids (a fake client).  A decision for the owner.
