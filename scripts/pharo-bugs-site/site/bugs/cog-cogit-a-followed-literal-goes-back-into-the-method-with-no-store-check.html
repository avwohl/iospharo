Record

  • Defect: stock Cog (v12.0.6, macOS arm64) stops with a segmentation fault in a full GC (markAndTrace, fixFollowedField:ofObject:withInitialValue:) in some runs of the tests of the package PharoMisc: 2 of 5 runs with the stock VM, 5 of 9 runs with a build of the same source and the stock plugins.

  • Cause: Cogit>>indexForSelector:in:at: looks at each literal of a method. It follows a literal that is a forwarder and writes the followed object back into the method with objectMemory longAt:put:. That store has no store check. When the method is old and the followed object is young, the method is not in the remembered set. The scavenges that come after do not update the literal, and the object moves or dies. The literal then has an address that holds another object or zeros. The next full GC reads that address.

  • The way to the state:

    • A test does become: on a literal Array of its method, with a new object (LoArrayAutomaticEventGenerationTest>>testReset of PharoMisc: subject collection: #(a b c)). The old Array is then a forwarder to a young object.
    • A compaction of the machine code zone frees the target of a linked send of that method before the next scavenge. The compaction unlinks the send and calls indexForSelector:in:at: (relocateIfCallOrMethodReference:mcpc:delta:).
    • A later test calls Smalltalk garbageCollect.

  • Evidence: a diagnostic print of the method at each GC shows that literal 0 changes from the old Array to the address of a young object. The method has no remembered bit, and the value stays for about 40 scavenges. A watch on the literal slot by page protection named the writer: indexForSelector:in:at:, called from compactCogCompiledCode. The diagnostics were local and are not in the change.

  • Change (one statement): the method writes the followed literal with storePointer:ofObject:withValue:, which remembers an old method that gets a young value. No other Slang source of the Cogit has this pattern.

  • The change is in Slang, so the build runs the code generation again.

  • Test (2026-11-17, macOS 27, arm64): the tests of PharoMisc with the package repairs of our run.

    VM Runs Runs with a segmentation fault
    build of the stock source, stock plugins 9 5
    the same build with the change 10 0 (361 tests, 360 pass, 1 failure, as on our VM)

  • No small script shows the defect. Three scripts made the forwarder and the compaction, and in each a store with the check repaired the literal first. The reproduction is the package row (PKG_FIXES_FILE=<work directory> with scripts/vmrun.sh pkgs --reuse, row 6).

  • Not tested: Linux, Windows, x86_64. A full sweep of the Pharo 14 tests on the Cog with the change is in work.

Names such as scripts/vmrun.sh and scripts/cogdiff/ are scripts of the iospharo repository, which runs one VM at a time. cog is stock Cog, cogp is Cog with the change, ours is iospharo.

Fix

A change of the Cog sources (pharo-project/pharo-vm, branch pharo-12), on the local branch fix/indexforselector-store-check. State: committed on the branch, tested with the package row that showed the crash. Not sent upstream.

Subject: [PATCH] Cogit>>indexForSelector:in:at: stores a followed literal
 without the store check

Defect: when a Cog compaction of the machine code zone frees the target of a
linked send, relocateIfCallOrMethodReference:mcpc:delta: unlinks the send and
calls indexForSelector:in:at:, which scans the literal frame of the sending
method.  A literal that is a forwarder (left by become:) is followed, and the
followed object is written back into the method with objectMemory longAt:put:.
That store skips the store check.  The sending method is usually old.  When
the become: made an old literal into a young object (the old object becomes a
forwarder to a young copy), the old method now refers to a young object, is not
in the remembered set and has no remembered bit.

How it shows (stock Cog v12.0.6, macOS arm64, found in the PharoMisc package
tests): the next scavenge neither updates nor traces the young literal.  The
young object moves or dies, and the literal of the method keeps the old address,
which later holds another object or zeros.  The next full GC finds the method
slot (markAndTrace), takes the stale value for a forwarder, and stops with a
segmentation fault in fixFollowedField:ofObject:withInitialValue: or in
markAndTrace.  The test LoArrayAutomaticEventGenerationTest>>testReset does
subject collection: #(a b c): the literal Array of the (old) test method is
become:d into a young LoSubjectArray, and later TkThreadTest>>testFinalization
calls Smalltalk garbageCollect.  A watch on the literal slot (page protection)
named indexForSelector:in:at: as the writer, called from compactCogCompiledCode.

Change: write the followed literal with storePointer:ofObject:withValue:, which
remembers the method when it is old and the value is young.
