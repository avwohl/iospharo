Record

  • Review: accepted (round 1).
  • Entries: scripts/image-fixes/20-network-tests.st
  • Methods: NetNameResolver class>>localHostAddress, NetNameResolverTest>>testLocalHostAddress, ZnHTTPSTest>>testSNIPage, ZnHTTPSTest>>testGetPharoVersion, ZnClientTest>>testQueryGoogle

Network works from the shell and from both VMs (DNS, HTTP, HTTPS through ZdcSecureSocketStream with the SSL plugin present), so no Apple network prompt blocked these runs. Four causes. (1) testLocalHostAddress was skipped as broken. The real defect is NetNameResolver class>>localHostAddress: stock Cog primitive (SocketPluginImpl.c sqResolverLocalAddress) looks only at interfaces eth0 and wlan0 so it answers 0.0.0.0 on macOS, and our VM primitiveResolverLocalAddress is a stub that always answers 127.0.0.1. The image method then answered loopback on a connected machine, which the test denies. Fix: when the primitive gives 0.0.0.0 or 127.x, use the address the host name resolves to (10.3.0.128 here), fall back to loopback; the skip is removed. (2) testSNIPage: the commented-out body works today (www.mnot.net redirects to mnot.net, ZnClient follows), so the body is restored with the other HTTPS tests' guards. (3) testGetPharoVersion was an empty skip; it now GETs https://get.pharo.org/64/stable and checks success and that the script text mentions Pharo. (4) testQueryGoogle: www.google.com answers a non-JavaScript client with an enablejs page (no results, no pharo.org), so the test fails on every VM; same test now queries https://www.bing.com/search?q=Pharo+Smalltalk with unchanged assertions (success, text/html, contains pharo.org). Search-engine dependence is as fragile as the original.

Only the Pharo 14 image was tested; the guards are written to be idempotent for Pharo 13 but not run there.

VM change: Both VMs are wrong about the local address; the image fix above hides nothing because the VM answers are still wrong and should be repaired too. (a) Our VM: src/vm/Primitives.cpp, Interpreter::primitiveResolverLocalAddress (~line 33375) always returns 127.0.0.1 instead of a real interface address; implement it like Cog with getifaddrs, returning the first non-loopback AF_INET address of an up interface. (b) Cog (for the owner to review before anything goes upstream; I made no PR): pharo-vm/plugins/SocketPlugin/src/common/SocketPluginImpl.c sqResolverLocalAddress (line ~1716) accepts only interface names eth0 and wlan0 (its own TODO says it is incomplete), so on macOS (en0) and many Linux names it returns 0, and Pharo's image comment says 'On Mac the primitive is buggy'. Proposal: drop the name test, take the first AF_INET address that is not 127.x and whose interface is IFF_UP. Reproducer: NetNameResolver primLocalAddress. Output: Cog #[0 0 0 0], ours #[127 0 0 1]; expected a LAN address such as #[10 3 0 128] on a connected machine (NetNameResolver addressForName: NetNameResolver localHostName gives 10.3.0.128 on both).

Open points: None for the four tests. Caveats: testQueryGoogle, testSNIPage and testGetPharoVersion depend on live third-party servers (bing.com, mnot.net, get.pharo.org) and will fail offline, as the original tests did. testLocalHostAddress would still fail on a connected machine whose host name resolves only to loopback. The Apple network prompt did not appear in these runs, so I made no workaround for it and did not investigate the prompt on the GUI app.

Upstream note: Pharo PR candidate (Network-Kernel, Network-Tests, Zinc tests): 'NetNameResolver class>>localHostAddress: use the host name address when the primitive gives none or loopback; un-skip NetNameResolverTest>>testLocalHostAddress; restore ZnHTTPSTest>>testSNIPage; implement ZnHTTPSTest>>testGetPharoVersion; ZnClientTest>>testQueryGoogle queries a search engine that serves non-JavaScript clients'. How to apply an entries file: file in 00-header.st and the entries file as one chunk (the iospharo script scripts/gen-image-fixes.py makes that chunk). Each entry checks for the defect first and prints FIXED, ADDED or SKIP. Download 00-header.st.

"network-tests cluster.  Entries only; see tools/fix_header.st."

"N1. NetNameResolver class>>localHostAddress: the primitive answers 0.0.0.0 on
macOS under stock Cog (the plugin looks only at the interfaces eth0 and wlan0)
and always 127.0.0.1 under our VM (the primitive is a stub).  The method then
answers the loopback address on a connected machine, which
NetNameResolverTest>>testLocalHostAddress denies.  When the primitive gives no
usable address, use the address that the name of this host resolves to."
fix value: #'NetNameResolver class' value: #localHostAddress
	value: [ :source | (source includesSubstring: 'primAddress = #[0 0 0 0] ifTrue:') ]
	value:
'localHostAddress
	"Return the local address of this host."
	"NetNameResolver localHostAddress"
	"The primitive can answer an empty address (stock Cog looks only at the interfaces eth0 and wlan0, so it answers 0.0.0.0 on macOS) or the loopback address (a VM that stubs the primitive).  In both cases use the address to which the name of this host resolves.  When that fails too, or is a loopback address, use the loopback address."

	| primAddress hostAddress |
	self initializeNetwork.
	[ primAddress := self primLocalAddress ] on: PrimitiveFailed do: [ :err | primAddress := #[0 0 0 0] ].
	(primAddress = #[0 0 0 0] or: [ primAddress first = 127 ]) ifTrue: [
		hostAddress := [ self addressForName: self localHostName ]
			on: NameLookupFailure
			do: [ :err | nil ].
		primAddress := (hostAddress notNil and: [ hostAddress size = 4 and: [ hostAddress first ~= 127 ] ])
			ifTrue: [ hostAddress asByteArray ]
			ifFalse: [ #[127 0 0 1] ] ].
	^ SocketAddress fromOldByteAddress: primAddress'.
