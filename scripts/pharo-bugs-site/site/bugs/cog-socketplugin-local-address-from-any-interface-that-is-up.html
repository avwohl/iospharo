Record

  • Defect: sqResolverLocalAddress accepts only interfaces with the names eth0 and wlan0. On macOS the primitive answers 0.0.0.0, and NetNameResolver localHostAddress is then the loopback address on a connected machine. The image has NetNameResolverTest>>testLocalHostAddress set to skip as "currently broken".
  • Change: take the first IPv4 address of an interface that is up and is not the loopback.
  • Test (2026-11-17, macOS 27, arm64, a Debug build of the branch): NetNameResolver primLocalAddress answers #[10 3 0 128]. The stock VM answers #[0 0 0 0]. Seven network test classes give the same results on the two VMs (73 tests pass, 1 skip).
  • Our VM had its own defect in the same primitive (a stub that answered 127.0.0.1). This repository has the fix for that defect.

Test

"Run in a Playground of a Pharo 14 image."
NetNameResolver primLocalAddress printString.
"Stock Cog on macOS answers #[0 0 0 0].  With the change: the address of an interface that is up."

Names such as scripts/vmrun.sh and scripts/cogdiff/ are scripts of the iospharo repository, which runs one VM at a time. cog is stock Cog, cogp is Cog with the change, ours is iospharo.

Fix

A change of the Cog sources (pharo-project/pharo-vm, branch pharo-12), on the local branch fix/resolver-local-address-any-interface. State: committed on the branch, tested. Not sent upstream.

Subject: [PATCH] SocketPlugin: local address from any interface that is up,
 not only eth0 and wlan0

sqResolverLocalAddress accepted only interfaces with the names eth0 and
wlan0.  On macOS (en0, en1, ...) and on a Linux with predictable interface
names (enp3s0, wlp2s0, ...) the primitive answered 0.0.0.0, and
NetNameResolver class>>localHostAddress then answered the loopback address
on a connected machine.  NetNameResolverTest>>testLocalHostAddress is set
to skip in the image as 'currently broken' for this reason.

Take the first IPv4 address of an interface that is up and is not the
loopback.  An interface that is also running, with an address outside
169.254/16, wins over one that is only up.  With no such interface the
answer stays 0.0.0.0.  The early returns no longer skip freeifaddrs.

Measured on macOS 27, arm64, interface en6 at 10.3.0.128:
  before: NetNameResolver primLocalAddress -> #[0 0 0 0]
  after:  NetNameResolver primLocalAddress -> #[10 3 0 128]
