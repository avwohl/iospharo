Record

  • Review: accepted (round 2).
  • Entries: scripts/image-fixes/20-WriteBarrierTest.st
  • Methods: TFFIBackend>>on:float64At:put:, TFFIBackend>>on:float32At:put:, WriteBarrierTest>>testMutateByteArrayUsingDoubleAtPut, WriteBarrierTest>>testMutateByteArrayUsingFloatAtPut

Both tests were marked expectedFailure and compared a byte (guineaPig first) with a Float, so they could never pass. The test bodies are repaired to compare (doubleAt: 1) / (floatAt: 1) with the stored value, and the expectedFailure pragma is removed. On our VM, prims 628/629 fail with PrimErrNoModification on a read-only receiver, and the image fallback TFFIBackend>>on:float64At:put: / on:float32At:put: now signals modificationForbiddenFor:index:value: (it only did primitiveFailed before). That makes both tests pass on our VM. Stock Cog v12.0.6 still fails both tests: its primitiveStoreFloat32IntoBytes / primitiveStoreFloat64IntoBytes never test for an immutable receiver, so the primitive writes into the read-only ByteArray and no ModificationForbidden is signalled. That is a Cog defect, which I cannot repair without editing VM sources; I give the exact proposal in vmChange for the owner to review. I did not hide the difference in the image. I did not re-run the test suites in this round; the pass counts quoted come from the earlier validated round, and this round I only re-read sources and ran small probes.

VM change: COG (owner review required before anything is filed; no PR made). File: pharo-vm/smalltalksrc/VMMaker/StackInterpreterPrimitives.class.st. Methods primitiveStoreFloat32IntoBytes (prim 628) and primitiveStoreFloat64IntoBytes (prim 629), and for consistency every other primitiveStore*IntoBytes (Boolean8, Char8/16/32, Int8/16/32/64, UInt8/16/32/64, Pointer). Defect: after the argument checks and before the write, the receiver is not tested for immutability, so a read-only ByteArray is overwritten. Proposal: after the (objectMemory isNonIntegerObject: index) / isFloatObject / argumentCount check and before 'bytes := objectMemory firstBytePointerOfDataObject: rcvr', insert (the same form that primitiveAtPut already uses at line ~2829 of that file): (objectMemory isObjImmutable: rcvr) ifTrue: [ ^ self primitiveFailFor: PrimErrNoModification ]. The image fallback then signals ModificationForbidden, as on our VM. Reproducer: g := ByteArray new: 8. g beReadOnlyObject. [g float64AtOffset: 0 put: 2.5. #wrote] on: ModificationForbidden do: [:e | #forbidden]. Cog: #wrote, g = #[0 0 0 0 0 0 4 64]. Ours: #forbidden, g all zero. OUR VM, related and not in this cluster (measured this round): the typed-write primitives 615-629 in src/vm/Primitives.cpp do check hdr->isImmutable() and fail, but the fallback chain ends in the named primitive primitiveFFIIntegerAtPut (Primitives.cpp:31931, registered Interpreter.cpp:25399), which has no immutability check; so on a read-only ByteArray g uint32AtOffset: 0 put: 7 and int32AtOffset:put: still WRITE on our VM (probe result #wrote, g = #[7 0 0 0 0 0 0 0]; the same output on Cog, where prim 620 has no check either). Proposal for our VM: in primitiveFFIIntegerAtPut, when the receiver argument is a heap object with isImmutable(), set primFailCode_ = PrimErrNoModification_ and fail; the image method TFFIBackend>>integerOfObject:at:put:size:signed: then needs a read-only branch like the float one. That is a separate defect from the two tests (no test of this cluster covers it) and I did not change it; the reviewer's remark that unsignedLongAt:put: and int32AtOffset:put: write silently is confirmed, but the cause is the FFI integer primitive and not prims 620/621 themselves.

21-write-barrier-integer-stores.st (download)
"Write barrier for the typed integer stores into a ByteArray (2026-11-17).

The typed store primitives 615-627 fail on a read-only ByteArray on our VM.
The fallback of each accessor goes through ByteArray>>integerAt:put:size:signed:
to the named primitive primitiveFFIIntegerAtPut.  That primitive wrote the
bytes of the read-only object on our VM (fixed in the VM on 2026-11-17: the
primitive now fails).  Stock Cog writes the bytes in the primitives 615-627
themselves (docs/upstream has the Cog change).

W1. With the two VM changes the fallback ended in PrimitiveFailed.  A store
into a read-only object must signal ModificationForbidden, as at:put: does, so
that a handler can make the object writable and retry.  The retry selector is
the index-based accessor of the same size and sign.

W2, W3. WriteBarrierTest has tests for at:put:, doubleAt:put: and floatAt:put:
on a read-only ByteArray, and none for an integer store.  Two tests with the
form of testMutateByteArrayUsingDoubleAtPut."

fix value: #ByteArray value: #integerAt:put:size:signed:
	value: [ :source | (source includesSubstring: 'isReadOnlyObject') not ]
	value:
'integerAt: byteOffset put: value size: nBytes signed: aBoolean

	self isReadOnlyObject ifTrue: [
		| selectors |
		selectors := aBoolean
			ifTrue: [ #( #signedByteAt:put: #signedShortAt:put: nil #signedLongAt:put: nil nil nil #signedLongLongAt:put: ) ]
			ifFalse: [ #( #unsignedByteAt:put: #unsignedShortAt:put: nil #unsignedLongAt:put: nil nil nil #unsignedLongLongAt:put: ) ].
		^ self
			  modificationForbiddenFor: (selectors at: nBytes)
			  index: byteOffset
			  value: value ].

	^ FFIBackend current
		  integerOfObject: self
		  at: byteOffset
		  put: value
		  size: nBytes
		  signed: aBoolean'.

add value: #WriteBarrierTest value: #testMutateByteArrayUsingUnsignedLongAtPut value: 'tests - object'
	value:
'testMutateByteArrayUsingUnsignedLongAtPut
	| guineaPig |
