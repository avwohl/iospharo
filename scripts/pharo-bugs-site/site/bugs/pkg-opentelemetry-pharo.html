Record

  • State before: the manifest row loaded the baseline with no group, and the image had no test class. With the group tests: 1034 tests, 1033 pass, 1 skip on the two VMs. The group integration-tests (3 tests) was not loaded.
  • The skip: OTOtlpGrpcSpanExporterTest>>testExportUsesGrpcTransportStackEndToEnd runs only when 9 classes of grpc-pharo are in the image. One of them, GRPCHTTP2MockStream, is in the package GRPC-Tests. The baseline of the package loads grpc-pharo with its default group, and that group does not have GRPC-Tests.
  • The 3 integration tests send one gRPC call each to an OpenTelemetry collector on 127.0.0.1:4317, and then read the file that the collector writes. The test machine runs no collector.
  • Repair here:
    • The manifest row loads the groups tests and integration-tests.
    • fixes/gabriel-darbord-opentelemetry-pharo.st defines GRPCHTTP2MockStream (a copy of the class of grpc-pharo v0.1.0).
    • The same file adds the class OTLPGrpcCollectorDouble: a receiver for gRPC on HTTP/2 in the image. The receiver decodes each request and writes the JSON file that the collector writes. The setUp of OTOtlpGrpcIntegrationTest starts the receiver and sets the environment variables that the tests read. No assertion has a change.
  • Limits: the receiver uses the HTTP/2 code of the GRPC package for the server side. A defect that the reader and the writer of that code share does not show. The receiver does not check the request headers or the rules of the OTLP data. The 3 tests are thus a check of the client against a receiver in the image, and not against the real collector.
  • Result: 1037 of 1037 pass on the two VMs.
