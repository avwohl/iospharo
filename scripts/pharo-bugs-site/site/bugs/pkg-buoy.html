Record

  • Defect: the package Buoy-Metaprogramming-Pharo-Extensions has an extension Symbol>>argumentCount ^ self numArgs. Pharo 14 has its own Symbol>>argumentCount ^ self numArgs + 1 (the receiver is the first argument when a symbol stands for a block), and Symbol>>valueWithEnoughArguments: depends on that value. The load of Buoy replaces the method of the image.
  • Effect: Metacello calls the post-load action of the baseline with valueWithEnoughArguments:. With the method of Buoy the argument array is empty, and the load stops with SubscriptOutOfBounds: 1 in #(). Each later use of a symbol as a block in the image has the same defect.
  • Repair: patches/ba-st-buoy.patch removes the extension and changes the one sender in Buoy (KeywordMessageSendingCollector) to numArgs.
  • State with the patch: the load works. 363 tests, 362 pass on the two VMs.
  • Second defect: OrderedDictionaryExtensionsTest>>testEquals is a copy of an old test of Pharo. It fills two dictionaries in opposite orders and expects that the two are equal. OrderedDictionary>>= of Pharo 14 compares the index of each key, so the order matters. The test of Pharo 14 itself fills the two in the same order.
  • Repair here: fixes/ba-st-buoy.st gives the test the form of the Pharo 14 test, with one more check that the opposite order is not equal.
  • Result with the two repairs: 616 of 616 tests pass on the two VMs (the class list now has each loaded package of the repository).
  • Packages that load Buoy as a dependency get the same defect: ba-st/Launchpad (row 14) and ba-st/Hyperspace (row 15) stopped in the load with SubscriptOutOfBounds: 1 in #(). The files locks/ba-st-launchpad.txt and locks/ba-st-hyperspace.txt make the load take Buoy from a local clone with the patch (a Metacello lock).

Fix

Fixes file (filed in after the load): ba-st-buoy.st (download)
"Buoy (ba-st/Buoy, release-candidate): OrderedDictionaryExtensionsTest>>testEquals
is a copy of an old OrderedDictionaryTest>>testEquals of Pharo.  It fills two
dictionaries with the same associations in opposite orders and expects that
the two are equal ('For equality, order will not matter').

OrderedDictionary>>= of Pharo 14 compares indexOfKey: for each key, so the
order matters.  The test of Pharo 14 itself (OrderedDictionaryTest>>testEquals)
fills the two dictionaries in the same order.  The test of Buoy fails on stock
Cog and on our VM with 'Got an OrderedDictionary(...) instead of an
OrderedDictionary(...)'.

The repair: the two dictionaries get the associations in the same order, as in
the test of Pharo 14, and a third dictionary with the opposite order must not
be equal."

fix value: #OrderedDictionaryExtensionsTest value: #testEquals
	value: [ :source | source includesSubstring: 'with: self orderedAssociations reversed' ]
	value:
'testEquals
	| dictionaryOne dictionaryTwo dictionaryThree |

	dictionaryOne := self emptyDictionary.
	dictionaryTwo := self emptyDictionary.
	self
		assertDictionary: dictionaryOne
		equals: dictionaryTwo.

	"Pharo 14: the order of the associations matters for equality"
	self orderedAssociations
		with: self orderedAssociations
		do: [:firstAssociation :secondAssociation |
			dictionaryOne add: firstAssociation.
			dictionaryTwo add: secondAssociation.
			self
				assertDictionary: dictionaryOne
				doesNotEqual: self emptyDictionary.
			self
				assertDictionary: dictionaryTwo
				doesNotEqual: self emptyDictionary.
			self
				assertDictionary: dictionaryOne
				equals: dictionaryTwo].

	"The same associations in the opposite order are not equal"
	dictionaryThree := self emptyDictionary.
	self orderedAssociations reversed do: [:each | dictionaryThree add: each].
	self assert: dictionaryThree size equals: dictionaryOne size.
	self
		assertDictionary: dictionaryOne
		doesNotEqual: dictionaryThree.

	self
		assertDictionary: dictionaryOne
		equals: dictionaryTwo'.
