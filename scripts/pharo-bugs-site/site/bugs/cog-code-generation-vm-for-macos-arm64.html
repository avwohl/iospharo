Record

  • Defect: cmake/vmmaker.cmake downloads the stock VM 10.3.2 to generate the C sources. On macOS 27 that VM stops at startup with "Could not allocate codeZone in the expected place (0x320000000)", and the build stops at the vmmaker step.
  • Change: download the release v10.3.12+0.4b0622446 for macOS arm64. The change has the URL and the SHA256 of that archive, in the form that the file uses for all platforms.
  • Test (2026-11-17): a build of the branch with no GENERATE_PHARO_VM completes, and the VM that the build makes answers 42 factorial.
  • Not checked: the other platforms keep their old VM, and no check was made that those start on current systems.

Names such as scripts/vmrun.sh and scripts/cogdiff/ are scripts of the iospharo repository, which runs one VM at a time. cog is stock Cog, cogp is Cog with the change, ours is iospharo.

Fix

A change of the Cog sources (pharo-project/pharo-vm, branch pharo-12), on the local branch fix/vmmaker-bootstrap-vm-darwin-arm64. State: tested, not committed: the change is a version pin, and the owner must approve a pin. Not sent upstream.
